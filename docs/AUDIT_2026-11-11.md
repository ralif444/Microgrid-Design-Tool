# Audit and refactor, 2026-11-11

> Scope: whole repository on branch `feat/cable-sizing`, commit `0476874`. The calculation engine (`engine/`) was audited and deliberately left unchanged. Nothing here is recorded in Doc 9 yet; section 5 has a draft entry.

## 1. Result

The project was in good order before this audit: every check and test passed, the layer rules are enforced by tools, and the test counts matched the last gate-log row. The audit found no defect in a calculation. It found two defects in error handling and one in the interface, removed some duplication, and left the outputs unchanged.

| Check | Before | After |
|---|---|---|
| Static checks (`tools/check.py`) | pass | pass |
| Engine tests | 53 | 53 |
| Backend tests | 514 | 528 (14 new) |
| Frontend unit tests | 101 | 101 |
| Browser tests | 69 | 70 (1 new) |
| Golden comparison, 204 API responses | — | byte-identical |

The golden comparison runs every analysis type on the test design and the five example Projects on both engines, plus verify, re-run, import, the error paths and the OpenAPI description, and compares the JSON before and after with volatile fields (record id, timestamp, engine commit) masked.

## 2. Defects fixed

| # | Defect | Before | After |
|---|---|---|---|
| 1 | A non-finite number in `parameters` (`Infinity`, `1e999`, an integer beyond the double range) passed stage 1. Doc 3 §1 says numbers are finite; the snapshot already enforced it, the free-form `parameters` object did not. | Real Engine: `UNAVAILABLE / ENGINE_ERROR`, logged as an engine defect. Fake Engine: `FEASIBLE`. `NaN` in a sweep range passed as valid. | `INPUT_INVALID / MALFORMED_REQUEST`, engine not called, same as a non-finite number in the snapshot. |
| 2 | A request body nested too deeply to decode raised `RecursionError`. | HTTP 500 `INTERNAL_ERROR` | HTTP 400 `MALFORMED_JSON` |
| 3 | On the six further-analysis screens (S-09 to S-14) a dismissed transport-error toast did not come back when the same failure happened again, because the screen compared the new message with the dismissed one. | No message on the repeated failure | The toast shows every time |

Defects 1 and 2 are reachable only by a hand-written request, not from the interface, because the browser never sends `NaN` or `Infinity`. Each has a regression test that fails on the old code.

## 3. Refactors (no behaviour change)

**Backend**
- `services/canonical.py` gains `snapshot_hash()` and `safe_sha256_hex()`. The rule "hash the snapshot alone, or with its scenarios" was written out in three places (pipeline twice, file check once) and the fallback hash in two. Creation and verification of a RunRecord now share one function.
- `services/limits.py`: the sweep point count is computed once for the two caps that use it.
- `api/routers`: one `read_body()` replaces five copies of the body-limit arithmetic.
- `MSG_ENGINE_ERROR` (was in the guard and in the Real Engine adapter) and `M4_POINT_METRICS` (was in validation and in the adapter) now live once in `domain/`, which both layers may import.

**Frontend**
- New `components/useAnalysisCall.ts` holds the request state (busy flag, transport error) that four screens and the shared hook each wrote out, and the single `SOLVER` constant that had four copies.
- `api-client`: one `post()` helper for all POST calls.
- `Further.fmt` uses the shared `num()` rounding.

**Documentation**
- `README.md`: the seam list of `tools/test.py` now names `engine`.

Net change in source: 28 files modified, 169 lines added and 190 removed, plus the new hook file (28 lines) and the tests in two test files.

## 4. Findings left as they are

| # | Finding | Why it was left |
|---|---|---|
| 1 | `mgengine.m3.m3b` and `m3d` are not called by the app; the adapter calls `evaluate` per point and computes the first infeasible value and the feasible fraction itself. Two implementations of the same two figures exist. | The engine is the object of the PSIM validation and its tests cover these functions. Changing it is a decision for the engine version, not a clean-up. |
| 2 | The execution guard cannot stop a run that exceeds the time budget; the thread is abandoned and keeps using CPU until it ends. | Documented decision (Doc 9 A-15). A real fix needs a process per run. |
| 3 | A request without a `Content-Length` header is read in full before the size limit is checked. | The server listens on the loopback address only. |
| 4 | The comment in `services/cable_sizing/tables.py` ("factor tables kept as plain JSON until the method reads them") is out of date: the method exists and still reads plain JSON. | Typing the factor tables changes the table file contract (D-101 K269). |
| 5 | `docs/design/` holds 807 review screenshots, 64 MB, which is nearly all of the repository's size. | They are gate evidence. Moving them out of git is the owner's choice. |
| 6 | Efficiency: no hot spot found. All analyses on the six test designs with the Real Engine finish in about 6 s in total. Loadability at every sweep point is the one costly option and already has its own cap (D-67). | Nothing to change. |
