# UI audit (2026-11-03, before the design system)

Screenshots of every route at 1440×900 and 1280×720 are in `audit-2026-11-03/<size>/`. They were taken with Playwright (bundled Chromium) on the Real Engine (mgengine 0.4.0). The project was example D2 with the Doc 3 §3.7 study limits, after M1, M2 and M4a had run. Navigation was client-side only, because the Project store lives in memory. Files named `*-fold.png` show only the first viewport; the others are full-page. Files named `*-after-run.png` show the screen straight after a run, before the user leaves it.

The app currently has 16 routes plus Start. S-17 About is not built. Today the whole visual layer is 33 lines of `frontend/app/globals.css` on top of browser defaults.

## Top 10 problems

| # | Problem | Evidence | Doc 7 rule it weakens |
|---|---|---|---|
| 1 | **Raw float output in result tables.** M1 results, power sharing, line flows and the M2 Sizing check print 15–17 significant digits, for example `49.87736081770318 Hz`, `0.43500482412376246`, `16.45530402571602`. Columns become unscannable, and the precision has no engineering meaning. K147 rounded only the M2 margin table. | `1440x900/06-power-flow-after-run.png` (System, Bus voltages, Inverter outputs, Line flows); `1440x900/07-constraint-check-after-run.png` (Sizing check); `1440x900/14-report.png` §5 | P2, §5.1 "numbers easy to scan" |
| 2 | **The header is one wrapped run-on line of 17 links**, separated by "·" and "\|". It wraps to three lines at both sizes. The logo wraps to three lines too. There is no current-step marker and no done, stale or blocked state per step, so the stepper of P1 / §3 does not visibly exist. | every screenshot, e.g. `1280x720/06-power-flow-fold.png` | P1 pipeline stepper, §3 |
| 3 | **Status banners repeat themselves, and two roles share one colour.** The headline and `result.message` say nearly the same thing on two lines ("Power flow completed: an operating point was found…" twice). `warning` (INFEASIBLE) and `error` (SOLVER_FAILED and others) share `#c62828`, and `attention` and `neutral` share `#546e7a`. The 6 px left border is the only colour cue, with no tint. | `1440x900/06-power-flow-after-run.png`, `07-constraint-check-after-run.png`; `globals.css` lines 8–11 | §5 distinct roles per Status |
| 4 | **Results vanish when the user leaves a screen.** After a run, the M1 table, the M2 verdict and the M4a modes are held only in screen-local state. On return, the M1 screen says "M1 result: current" but shows no result. Only the Report shows it again. | `06-power-flow-after-run.png` against `06-power-flow-fold.png` (same session, M1 still current) | P2 (the status is lost along with the result). The fix belongs to the store, so it is out of scope for a presentation-only change; it is listed so it is not mistaken for a styling issue. |
| 5 | **Table alignment is inconsistent.** Header cells are right-aligned, but body cells are left-aligned, because `<html lang="id">` makes the `td:lang(id)` rule match every cell. Numbers therefore do not sit under their headers, and because they are not tabular, decimal points do not line up. | `07-constraint-check-after-run.png` (Value, Limit, Margin), `15-runs-fold.png`, `06-power-flow-after-run.png` | brief: numbers right-aligned with tabular-nums, text left |
| 6 | **Units sit in the cells, not the column header, in the M2 and Report margin tables.** Every row repeats "pu", "Hz" or "ratio", while the M1 tables put the unit in the header. The two conventions are mixed on one page in the Report. | `07-constraint-check-after-run.png`, `14-report.png` §3 against §5 | P3 units next to every field (consistency) |
| 7 | **Forms are unstructured.** Labels and inputs sit inline at random x-positions, with no column alignment, no grouping of required and optional fields, and native unstyled controls. The file input "Choose File / No file chosen" sits in the global header. Tabs on Network are plain buttons with no selected state. | `03-sizing.png`, `07-constraint-check-fold.png`, `04-network.png` (tabs), header in all | §6.2, §6.3 wireframes; P6 readiness |
| 8 | **The page has no hierarchy or density control.** h1 is ~32 px on every screen. Section captions (bold `caption`) and h2 differ only by weight, there is no surface or card separation, and there is no max width: the Loadability line runs 1 400 px wide at 1440. Most of each fold is empty white, while the Report is a 3 362 px single column. | `02-loads.png`, `04-network.png`, `07-constraint-check-after-run.png` (Loadability), `14-report.png` | brief: dense but calm |
| 9 | **Focus is not designed, and the page language is wrong.** Focus relies on the browser default ring, and the only custom outline is `tr.focus` (orange, the same hue as caution). `<html lang="id">` is set while every label is English (Doc 7 §8). Screen readers would read English text with Indonesian rules, and the `td:lang(id)` hack exists only because of this. | `frontend/app/layout.tsx`, `globals.css` lines 21 and 33 | §8 keyboard, visible focus; language |
| 10 | **Advisory, Fake and status treatments are under-specified.** The advisory box is a grey dashed border that looks like a disabled area. Its tag is all-caps body text with no "Advice" chip. The Fake note is a yellow highlight that matches no status role. The engine badge wraps ("Engine: / REAL"). The bus-voltage chart in the Report clips its own value labels (`0.98864732755…`). | `07-constraint-check-after-run.png` (Sizing check), `14-report.png` §5 chart, header badge in all | P4 advice differs visibly; P2 engine kind visible |

Also seen, but lower priority:
- Hash columns in the Report traceability table overflow into ~3 lines because of the 200 % zoom wrapping rule.
- Run history shows full ISO timestamps with microseconds.
- The Start screen has no visual difference between "new project" and "examples".

## Not checked

- Real screen reader output.
- Contrast of the *current* UI: there is no claim, as before (D-68).
